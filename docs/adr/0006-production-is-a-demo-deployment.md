# ADR-0006: Production is a demo deployment

Date: 2026-09-02
Status: Accepted

## Context

Aqd needed somewhere to live that costs nothing: Vercel Hobby, Supabase Free,
the Gemini free tier, Resend Free. An audit before configuring any of it found
five things that stood between the repo and a deployment, of which two were
not about cost at all.

**`dev_peek_code` was reachable in production.** Migration `0007` grants it to
`authenticated`, and PostgREST exposes every such function at `/rest/v1/rpc/`.
The application layer refuses to call it outside development, but the
application layer is not its only caller: anyone holding a session — including
someone who has just entered a stolen password and is sitting on the device
challenge — could read the code that was about to be emailed to the account's
real owner. Not cross-user exposure, not privilege escalation, but the
device-trust second factor defeated for exactly the attacker it exists to
stop.

**Email cannot reach strangers.** `EMAIL_FROM` is Resend's sandbox sender,
which delivers only to the Resend account holder's own address. Without a
verified domain there is no signup, no reset and no device challenge for
anybody else.

**The worst-case AI call did not fit.** Four attempts at a 15-second timeout
plus backoff is 67 seconds per task, plus an OpenRouter fallback after that,
against a 60-second ceiling — and no `maxDuration` was declared anywhere, so
the platform default of 10 seconds applied instead, which is shorter than a
healthy analysis.

**The Gemini free tier trains on its input.** Google states that content sent
to non-paid services may be used to improve their products and may be seen by
human reviewers, and says not to send confidential information. This product's
entire input is confidential legal documents.

## Decision

**Production is a demo, and every other decision follows from saying so.**
Signups are closed at the Supabase level, the only content is a synthetic
contract committed to the repo, and the deployment is never to receive a real
document. That is what makes the free Gemini tier a defensible choice rather
than a quiet liability: there is nothing confidential to leak.

**`dev_peek_code` is dropped, not disabled.** Migration `0020` removes the
function; `supabase/seed.sql` recreates it locally, and seed files are never
applied by `db push`. The property we want is that the function does not
exist, not that it declines — a flag can be flipped, and a guard only stops
the callers somebody thought of.

**Signups close at the source.** `enable_signup = false` on the Supabase
project is the gate; `SIGNUPS_CLOSED` only decides whether the signup screen
offers a form or explains why it doesn't. They can disagree, which is why the
runbook's verification step POSTs the signup action and reads the answer.

**The AI budget is a wall-clock budget.** Two attempts, 15s each, plus one
fallback call: 46 seconds, declared alongside `maxDuration = 60` on every
route that can reach a model. The retry count was tuned against a hanging
upstream; it is now bounded by the invocation that has to contain it.

**The demo content is seeded as data, not generated.** `seed-demo.sql` writes
clauses, analyses, findings and evidence directly. The clause text is
byte-identical to what ingesting the two drafts would produce, because it was
generated by running the real segmenter over them. The analysis rows are
asserted rather than derived — the one thing in the seed that is not evidence
about the pipeline — in exchange for a demo that costs no quota and cannot be
broken by a provider outage while somebody is looking at it.

**The database is kept awake.** Supabase Free pauses a project after seven
idle days, which is the exact shape of a portfolio link. A daily Vercel cron
hits `/api/health`, which runs one real query. When the database is
unreachable anyway, `src/proxy.ts` rewrites to a page that says the demo is
waking up rather than letting the generic error boundary tell a first-time
visitor the product is broken.

**The upload cap is 10 MB, in code.** It was 50 MB, chosen against Supabase's
per-file limit. The binding constraint is time, not bytes: a 50 MB document
cannot finish ingest inside 60 seconds, so the old limit did not reject that
upload — it accepted it and then died at the wall clock.

## Consequences

The deployment is honest about what it is, in the product rather than only in
the README: a visitor who reaches `/signup` is told this is a demo running on
free infrastructure with synthetic contracts.

Local development is unchanged. `SIGNUPS_CLOSED` is unset, so the e2e signup
journey still runs; `supabase db reset` still installs the code reveal; the
upload limit is env-overridable.

Two costs accepted. The AI layer is less resilient than it was — one retry
instead of three — which is a real reduction bought by the certainty that a
degraded upstream produces an error rather than a killed function mid-write.
And the seeded analysis is a fixture: nobody should read those findings as
evidence that the analyser produces findings like those.

The path off the demo is short and is deliberately a configuration change
rather than a rewrite: verify a domain in Resend and change `EMAIL_FROM`, move
Gemini to the paid tier, re-enable signups. The code does not encode
"demo-ness" anywhere except one flag and one seed file.

## Alternatives rejected

**Guarding `dev_peek_code` with a database flag.** Leaves the brute-force loop
in the database and makes safety depend on a setting nobody audits.

**Buying a domain to open the demo to visitors.** A shared demo account would
mean every visitor's device challenge lands in one shared inbox, where any
visitor can read any other's code — buying a domain in order to weaken the
second factor.

**Moving analysis into a background job.** The right answer eventually, and
the wrong one for a deployment task: it is a queue, a worker and a status
model, none of which the 60-second ceiling actually requires once the retry
budget fits inside it.

**Seeding by running a real analysis at deploy time.** Costs quota on every
rebuild, and makes the demo's content depend on a provider being healthy at
the moment somebody clicks the link.
